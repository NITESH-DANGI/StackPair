§1  Overview & Objectives
M-00 is the public-facing landing page of StackPair, served at the root URL /. It is the first thing any visitor sees — before login, before signup, before any product interaction. Its single job is to convert a curious developer into a registered user.
Unlike every other module, M-00 has no backend dependency. It is a fully static Next.js page (SSG), deployed to Cloudflare CDN, and loads with zero API calls. The only dynamic element is a live user count pulled from a public stats endpoint.
1.1  Strategic Purpose
Primary conversion goal: visitor → signup. Every design decision serves this.
Cold-start acquisition channel: the Portfolio Card Generator (/card) links back here. Landing page must capture that traffic.
Brand first impression: StackPair is technical, clean, and confident — not hype-y. Copy is direct and developer-specific.
SEO foundation: landing page is the primary organic search entry point for queries like "peer learning platform India" and "developer skill verification".
1.2  Objectives
Communicate the StackPair value proposition in under 10 seconds above the fold
Drive signups via primary CTA (Get Started Free) and secondary CTA (See How It Works)
Showcase all three modes — Learn, Build, Showcase — with concrete, visual examples
Feature the Portfolio Card Generator as a zero-friction entry point (no login required)
Build trust: show skill verification methodology, developer testimonials, and live user count
Achieve Lighthouse score ≥ 95 on Performance, Accessibility, Best Practices, SEO
1.3  Scope
In Scope: All sections of the / route. /about, /privacy, /terms static pages. Shared Navbar and Footer components used by /card and /showcase. SEO meta tags. OG image generation.
Out of Scope: Any authenticated UI. Pricing/billing logic (belongs to M-13). The Card Generator itself (belongs to M-12 — only a teaser section here). Post-signup flows (F-01).

5.2  Key Component Details
components/public/Navbar.tsx
Props
None — reads session via Supabase SDK client-side
Scroll state
useScrollPosition hook: tracks window.scrollY. isScrolled = scrollY > 80.
CTA logic
if (session && user.onboarding_state === "ACTIVE"): show "Go to App" → /learn. Else: show "Log In" + "Get Started".
Mobile drawer
useState: isMenuOpen. Framer Motion AnimatePresence: x: "100%" → x: 0 slide-in. Overlay backdrop with onClick close.
Active link
useIntersectionObserver: watches section IDs. Updates activeSection state. Nav link matching activeSection gets brand-blue colour.
components/landing/StatsBar.tsx
Data
usePublicStats() hook — reads from /public/stats with SWR. Returns stats or fallback values.
Animation
useIntersectionObserver on the section root ref. When isVisible becomes true, start CountUp for each stat simultaneously.
CountUp
Uses CountUp from M-01 design system (components/animation/CountUp.tsx). Duration 1200ms, ease-out.
Fallback
process.env.NEXT_PUBLIC_STAT_FALLBACK_DEVELOPERS etc. defined in .env.local and Vercel env vars.
components/landing/VerificationSection.tsx
Platform bar
Pure CSS horizontal stacked bar. Each platform is a flex segment with width proportional to its weight. No chart library.
Level scale
6 circles (0–5). Each circle: 48px diameter, coloured dot, label below, description tooltip on hover.
Animation
Level circles fill in sequentially on scroll-in: 0ms, 100ms, 200ms, 300ms, 400ms, 500ms delays using Framer Motion stagger.
lib/hooks/usePublicStats.ts
Returns
{ stats: PublicStats, isLoading: boolean, error: Error | null }
Fetching
useSWR with key "/public/stats". revalidateOnFocus: false. refreshInterval: 300000 (5 min).
Fallback
